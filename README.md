# 全屋网络与家庭私有云

> 把一条"只能上网"的家庭宽带链路，重构成**分层隔离、可运营的多租户私有云**。

一套面向"自住 + 出租"混合场景的网络与私有云架构设计：对外一张网，对内三个互不可见的信任域，其上叠加四项可交付服务——网络质量优化、智能家居中枢、全域广告过滤、私有存储与自动备份。

---

## 为什么做这件事

家庭网络通常是"单层扁平结构"：一台路由拨号，所有设备——家人的手机、租客的电脑、智能家居、存储服务器——共处同一个广播域。这带来三个被长期忽视的问题：

| 问题 | 具体表现 |
|---|---|
| **没有租户隔离** | 出租楼层的网络与自住网络共处同一广播域，隔离只能靠"没人去看"，而不是靠防火墙规则保证 |
| **没有账号体系** | 存储服务器只是一块共享盘，没有成员隔离、没有配额、没有自动备份闭环 |
| **没有边界意识** | 智能家居设备与私有存储同域，一台被攻破的廉价设备就能横向触达全部数据 |

这个项目的目标，是把"装了几个软件"变成**一套有结构的系统**。

## 核心设计：三个互不可见的信任域

```mermaid
flowchart TB
    ISP[运营商宽带] --> MODEM[光猫 · 桥接模式]
    MODEM --> R1[主路由 · PPPoE 拨号]
    R1 --> SR[软路由 · OpenWrt<br/>三层策略网关 · 域间默认 DROP]
    SR --> A[家庭域 LAN-A<br/>成员设备 + IoT 子域]
    SR --> B[租客域 LAN-B<br/>独立 VLAN / 独立 SSID]
    SR --> C[私有云域 LAN-C<br/>NAS · Home Assistant · AdGuard]
    C -. 加密隧道 .-> RA[外出远程访问]
```

| 域 | 承载 | 可达 | 不可达 |
|---|---|---|---|
| **LAN-A 家庭域** | 成员手机 / 电视 / 智能家居 | 互联网、家庭服务、自己的私有云目录 | 租客域、私有云管理面、他人目录 |
| **LAN-B 租客域** | 出租楼层租客设备 | 互联网出口、家庭服务（DNS） | 家庭域、私有云域（NAS 全部目录）、其他租客 |
| **LAN-C 私有云域** | NAS / Home Assistant / AdGuard | 互联网（仅必要端口） | 被任何客户端横向扫描 |

**隔离实现要点**

- 租客域使用独立 VLAN + 独立 SSID + 独立子网，软路由承担三层网关
- 域间默认策略 `DROP`，仅白名单放行 DNS（53/853）、NTP、DHCP
- 私有云域关闭客户端间横向通信（AP/交换机端口隔离或网段内 ACL）
- 租客之间是否互不可见（按租户再分子网）取决于 VLAN 数量与运维成本；默认先保证「租客 ↔ 家庭 / 私有云」的隔离
- IoT 设备单独成域，只允许中枢单向访问，收敛横向渗透面

## 功能分层

应用层的用户价值由服务层提供，依赖网络层的策略与接入层的物理链路——**下层没打好，上层全是沙上城堡**。

```mermaid
flowchart TB
    subgraph L4[应用层 · 住户感知到的价值]
        direction LR
        V1[网络质量优化] --- V2[智能家居控制] --- V3[无广告上网] --- V4[自动备份] --- V5[远程访问]
    end
    subgraph L3[服务层 · 提供价值的软件]
        direction LR
        S1[AdGuard Home] --- S2[Home Assistant] --- S3[备份服务] --- S4[Tailscale]
    end
    subgraph L2[网络层 · 决定谁能看见谁]
        direction LR
        N1[VLAN 与网段规划] --- N2[域间防火墙策略] --- N3[SQM / QoS 流控] --- N4[本地 DNS 缓存]
    end
    subgraph L1[接入层 · 物理链路与硬件]
        direction LR
        P1[光猫桥接] --- P2[主路由拨号] --- P3[AP / 交换机] --- P4[NAS 存储]
    end
    L1 --> L2 --> L3 --> L4
```

## 主要功能

1. **多租户网络隔离** —— 802.1Q VLAN + 独立 SSID + 独立网段划分三个互不可见的信任域，域间默认 `DROP`、仅白名单放行基础服务。
2. **全域广告过滤** —— AdGuard Home 统一接管全屋 DNS，终端零配置生效；分层治理，明确区分「DNS 域名层能拦的」与「拦不到的」。
3. **跨品牌智能家居接入** —— Home Assistant 作为统一控制中枢，本地协议优先，支持通过自定义组件接入无官方 SDK 的设备，断网仍可控。
4. **家庭私有云与自动备份** —— 「账号 + 独立目录 + 容量配额」三级权限模型，设备接入家庭网络即触发增量同步。
5. **远程安全访问** —— Tailscale / WireGuard 加密隧道，存储与管理端口零公网暴露。
6. **网络质量优化** —— SQM / QoS 智能流控治理缓冲区膨胀，本地 DNS 缓存与并行上游解析降低解析耗时。
7. **可观测与运维** —— 资源与服务存活监控看板、异常告警、配置版本化与一键备份恢复。

## 关键设计决策

| 决策点 | 建议方案 | 理由 |
|---|---|---|
| 楼层隔离实现 | VLAN + 独立 SSID | 复用现有硬件，无线侧同样可隔离 |
| 广告过滤位置 | 本地 AdGuard Home | 数据不出户，规则可自定义，配合抓包闭环 |
| 智能家居中枢 | 先容器化，资源吃紧则迁独立设备 | 低配小主机内存是明确瓶颈 |
| 远程访问 | Tailscale / WireGuard 隧道 | 不依赖公网 IP，暴露面最小 |
| 广告拦截边界 | 明确区分 L1 / L2 / L3 三层能力 | 提前管理预期，不承诺拦不掉的 |

## 量化目标

| 目标 | 指标 |
|---|---|
| 隔离有效 | 越权可达端口数 = 0 |
| 广告过滤 | DNS 层拦截率 ≥ 15%，误杀率 < 1% |
| 网络质量 | 内网延迟抖动 < 2ms，DNS 平均解析 < 30ms |
| 备份闭环 | 增量备份成功率 ≥ 99%，接入 WiFi 后 5 分钟内完成 |
| 远程可用 | 外出访问可用性 ≥ 99% |
| 可维护 | 任一变更 15 分钟内可回滚 |
